# 月末邮件与物料汇总 Spec

## 目标

在 `meidi-auto` 中统一实现以下链路：

```text
QQ 邮箱目标邮件
  -> 按月份选择最后一天 24:00 前最新邮件
  -> 保存附件月末快照与邮件清单
  -> 以库存表表头月末日期确认快照有效性
  -> 合并历史月末文件
  -> 按完整物料编码汇总
  -> 按公司、物料和业务类型汇总领用/借用/归还/退货等明细
  -> 输出带数据质量信息和趋势图表的 Excel 报告
```

现有每日库存邮件流水线（`main.py`）保持不变；月度汇总是独立入口，不应因月度报告失败而阻断每日生产邮件。

## 代码与运行边界

- 唯一代码源：`meidi-auto` GitHub `main`。
- 唯一执行环境：WSL 中的 `meidi-auto/.venv`。
- 邮箱凭据：WSL 本地 `.env` 或 GitHub Actions Secrets，禁止提交。
- 业务数据：继续保存在 Windows/坚果备份目录，通过 WSL `/mnt/c/...` 访问，禁止上传 GitHub。
- 原来的 `手动触发下载邮件` 目录只作为迁移对照，验证完成后才删除。

## 本地配置

```env
EMAIL_ADDRESS_QQ=...
EMAIL_PASSWORD_QQ=...
IMAP_SERVER=imap.qq.com
IMAP_MAILBOX=INBOX

MONTHLY_ARCHIVE_DIR=/mnt/c/Users/ishel/Desktop/坚果备份/A四川和裕达新材料有限公司/32重庆-美的/美的发货/月度汇总
MONTHLY_REPORT_DIR=/mnt/c/Users/ishel/Desktop/坚果备份/A四川和裕达新材料有限公司/32重庆-美的/美的发货/月度汇总/分析结果
LATEST_MAIL_DIR=/mnt/c/Users/ishel/Desktop/美的发货
TARGET_MAIL_SUBJECT=物料情况和Excel文件
TARGET_ATTACHMENT_PATTERN=总库存*.xlsx
```

`RECIPIENT_EMAILS` 等每日发送配置继续由生产流水线使用。月度下载不复用每日步骤的文件目录，避免中间文件相互覆盖。

## 邮件选择判据

对于目标月份 `YYYY-MM`：

1. 计算北京时间月末截止点 `YYYY-MM-last 23:59:59.999999+08:00`。
2. 在 IMAP 邮箱中查找主题包含 `TARGET_MAIL_SUBJECT` 的邮件。
3. 只接受包含匹配 `TARGET_ATTACHMENT_PATTERN` 的 `.xlsx` 附件。
4. 优先使用 IMAP `INTERNALDATE` 解析后的北京时间；缺失时回退到邮件 `Date` 头，并过滤 `received_at <= cutoff`。
5. 选择候选中时间最新的一封；没有候选时明确失败。
6. 使用 `BODY.PEEK` 和只读邮箱选择，不能改变邮件已读状态。

邮件搜索可以先用 IMAP `SINCE/BEFORE` 缩小范围，但最终必须用解析后的带时区时间再次判断，不能仅依赖 IMAP 日期粒度。

## 月末快照

自动下载的文件放在：

```text
月度汇总/自动月末归档/YYYYMM月底.xlsx
月度汇总/原始月末快照/YYYYMM_<received_at>_<attachment>.xlsx
月度汇总/原始月末快照/manifest.jsonl
```

自动归档优先于根目录中人工维护的 `YYYYMM月底.xlsx`；自动归档缺失时才使用人工文件。根目录的人工文件不会被程序覆盖。

清单至少记录：目标月份、邮件主题、邮件时间、邮件 UID、附件名、文件 SHA256、明细最后日期、当天出入库行数和校验结果。

## 工作簿校验与汇总

输入工作簿要求存在 `库存表`，表头可位于前 10 行内，至少包含：

- `物料编码` 或 `编号`
- `物料名称`
- `单位`
- `外仓入库总量`
- `外仓出库总量`
- `库存`

主键采用完整 `物料编码`；缺失时才回退到 `编号`。输出同时保留 `物料编码`、`编号`、`物料名称`、`单位`。

每种物料统计：月度入库、月度出库、月末库存、合格仓库存、外应存、月计划、累计入库、累计出库、净变化、月均数量和有业务月份数。

月末文件的主有效性判据是 `库存表` 物料表头上方的日期列：必须能解析出目标月份最后一天（例如 `2026年08月31日`）。这是库存快照日期，不要求当天一定发生出入库业务；找不到该日期的工作簿会标记为错误并跳过汇总。

`出入库明细表` 若存在，则额外检查：

- 最后明细日期；
- 是否包含月末当天记录；
- 是否存在晚于月末的记录。

没有月末当天业务时不判定快照失败，仅在 `数据质量` 中保留辅助提示；命令行以 `ℹ️` 输出，避免把“当天无业务”误报成月末文件不合格。

## 公司领用与业务分析

月度结算成功后还会生成固定路径的自动清单 `自动预警清单/list.xlsx`（同时按月份保存历史副本）。
近三个完整月份的每种物料出库总量记为 `Q`，清单字段按以下规则更新：

- `外应存 = Q / 12`；
- `家应存 = Q / 12`；
- `月计划 = Q / 3`；
- `备注` 只从上一版清单继承，人工修改不会被覆盖。

每日流程优先读取自动清单；自动清单尚未生成时才回退旧版 `script/data/list.xlsx`。

清单路径与留存：

- WSL/Windows 同步盘当前清单：`月度汇总/自动预警清单/list.xlsx`（由 `AUTO_LIST_FILE` 指定）；每日流程优先读取它。
- 坚果云 WebDAV 当前清单：`NUTSTORE_REMOTE_AUTO_LIST_FILE` 指定的同一相对路径。
- 每次月末核验通过后，当前清单会覆盖更新，同时在 `月度汇总/自动清单历史/YYMM.xlsx` 留存当月副本；WebDAV 模式也同步该历史副本。
- 若月末每日归档与目标邮件附件指纹不一致，则不更新报告、当前清单或历史清单，只发送人工核验通知。

从 `出入库明细表` 读取 `美的编码`、`物料品名`、`库存变动类别`、`本期收入`、`本期发出`、`备注`、`客户子库` 和 `出入库日期`。有备注时以备注为来源，并将“渝丰和、郅塑、松亚/松垭”等简称统一为完整公司名；备注为空时按已确认规则将 `MA1111` 归为“重庆工厂”，`MA1141` 和 `MS1121` 直接作为统计公司名；其他无法识别的记录保留为 `未备注`，不能静默丢弃。

业务类型至少区分：`领用出库`、`借用出库`、`借用归还`、`普通入库`、`退货/换货`、`不合格品调入`、`不合格品调出` 和 `借用/退换混合`。原始变动类别和备注同时保留，便于复核边界案例。

报告额外输出：

- `公司月度领用`：每月每家公司每种物料的领用出库量和笔数；
- `公司年度领用`：每年每家公司每种物料的领用出库量和笔数；
- `公司月度汇总`、`公司年度汇总`：直接按公司排名的领用总量、出库笔数和物料种类数；
- `公司业务汇总`、`公司业务明细`：借用、归还、退货、调拨和不合格品等完整业务；
- `公司领用趋势`、`公司年度趋势`、`业务类型趋势`：供图表和进一步分析使用；
- `图表`：公司月度领用、年度领用和业务类型趋势图；公司趋势数据保留全部公司，不隐藏小体量公司。

每日邮件 HTML：物料趋势和前五大公司明细均仅展示五位简写编号、月份、今日变化和单位，不再占用完整编码/名称列；汇总信息采用左右两组“项目+数值”四列布局。表格使用固定列宽、横向滚动、隔行底色和今日变化高亮，兼顾桌面邮件与窄屏查看。

## 输出报告

默认输出到 `MONTHLY_REPORT_DIR`，使用带时间戳的新文件名，不覆盖历史报告：

```text
月度物料分析_YYMM-YYMM_YYYYMMDD_HHMMSS.xlsx
```

工作表：

| 工作表 | 内容 |
|---|---|
| `物料总览` | 每种物料累计、净变化、最新库存 |
| `入库汇总` | 物料按月份展开的入库量 |
| `出库汇总` | 物料按月份展开的出库量 |
| `库存趋势` | 物料按月份展开的月末库存 |
| `计划与库存` | 月计划、外应存、库存等可用字段 |
| `物料明细` | 一行一个物料-月份组合和来源文件 |
| `数据质量` | 月份、邮件、字段、日期和数值校验 |

## CLI 约定

```bash
# 下载指定月份的月末邮件、归档并生成全量报告
python tools/monthly_summary.py --month 2026-08

# 不访问邮箱，仅使用已归档的月末文件生成报告
python tools/monthly_summary.py --aggregate-only

# 只检查配置、候选文件和月份，不写入文件
python tools/monthly_summary.py --month 2026-08 --dry-run

# 下载最新目标邮件供人工查看，不参与月末汇总
python tools/download_latest_mail.py
```

## 验收标准

1. 新旧邮箱下载逻辑对同一封目标邮件得到相同主题、附件名和附件 SHA256。
2. 对现有 `2502月底.xlsx` 至 `2607月底.xlsx` 扫描结果为 18 个月连续月份，必要字段全部通过。
3. `2502-2603` 的入库/出库汇总与现有历史汇总对账一致。
4. 重复月份、缺失月份、无候选邮件、缺少字段和月末日期缺失都能在报告中明确显示。
5. `.env`、邮件附件、月度 Excel、分析结果均不会进入 Git。
6. 原有 `main.py` 每日流水线的测试和 `--check/--dry-run` 行为不变。
